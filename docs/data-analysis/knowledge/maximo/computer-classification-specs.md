## 1. 사용자가 제시한 분류와 Actual CI의 구분

CLASSUSEWITH.OBJECTNAME을 조회해 적용 객체를 확인했다. 같은 속성 이름이 있어도 분류 ID와 스펙 템플릿은 별개다.

| 계열 | 확인된 분류·계층 | 적용 객체 |
| --- | --- | --- |
| 사용자 화면 CIROOT 계열 | CIROOT → CI.COMPUTERSYSTEM / CI.OS / CI.FILESYSTEM / CI.IPADDRESS / CI.SOFTWAREIMAGE / CI.SOFTWAREMODULE | CI |
| Computer의 하위 분류 | CI.VIRTUALCOMPUTERSYSTEM, CI.UNITARYCOMPUTERSYSTEM, CI.LINUXCOMPUTERSYSTEM, CI.WINDOWSCOMPUTERSYSTEM, CI.AIXCOMPUTERSYSTEM, CI.VMWARECOMPUTERSYSTEM 등 | CI |
| OS·파일시스템·IP의 하위 분류 | CI.LINUXOS, CI.WINDOWSOS 등 / CI.UNIXFILESYSTEM, CI.WINDOWSFILESYSTEM / CI.IPV4ADDRESS, CI.IPV6ADDRESS | CI |
| 사용자 화면 IT 계열 | IT → GENCSYS / WSAPPSER / ZCSYS | CI |
| Actual CI의 Computer 계열 | ACTUALCIROOTCLASS → SYS.COMPUTERSYSTEM / SYS.VIRTUALCOMPUTERSYSTEM / SYS.UNITARYCOMPUTERSYSTEM / SYS.GENERICCOMPUTERSYSTEM 등 | ACTCI |

전체 CI·ACTCI 계층을 조회하고 PARENT를 따라 하위 분류를 확인했다. 사용자 제공 2뎁스 목록으로 검색을 제한하지 않았다.
SYS.VIRTUALCOMPUTERSYSTEM은 이 환경에서 SYS.COMPUTERSYSTEM의 자식이 아니라 루트 아래 별도 분류다.

SYS.COMPUTERSYSTEM 아래에는 SYS.CPU, SYS.MEMORY, DEV.DISKDRIVE, SYS.OPERATINGSYSTEM,
SYS.FILESYSTEM, NET.L2INTERFACE, NET.IPINTERFACE 등이 등록돼 있다.
SYS.OPERATINGSYSTEM 아래에는 APP.SOFTWAREINSTALLATION이 있다.
이 PARENT 구조는 분류 트리이며 실제 Computer→CPU 등 관계 행의 존재를 뜻하지 않는다.
실제 연결 가능 설정은 아래 RELATIONRULES에서 별도로 확인했다.

## 2. 스펙 적용·자료형

선택 조회한 ACTCI 분류들은 CLASSUSEWITH의 ACTCI 설정과 각 CLASSSPEC의 ACTCI용 CLASSSPECUSEWITH가 존재한다.
ASSETATTRIBUTE는 ID와 ASSETATTRID가 모두 일치하며, 해당 스펙의 MANDATORY=0, USEINSPEC=1이다.
INHERITEDFROMID는 비어 있고 APPLYDOWNHIER=0이다. 부모의 모든 속성을 자식이 자동 보유한다고 가정할 수 없다.

SYS.COMPUTERSYSTEM과 SYS.VIRTUALCOMPUTERSYSTEM은 조회된 속성 ID·자료형·단위 구성이 같다.
아래 ACTCI 스펙의 CLASSSPEC.MEASUREUNITID와 ASSETATTRIBUTE.MEASUREUNITID는 모두 비어 있다.
숫자 타입만으로 GB/MB/byte, GHz/MHz, 시간의 epoch 단위를 확정할 수 없다.

비교한 CI.COMPUTERSYSTEM에는 COMPUTERSYSTEM_MEMORYSIZE, NUMCPUS, CPUSPEED 등 요약 속성이 있다.
GENCSYS에는 MEMSIZE(분류 단위 GBYTE), CPUSPEED(GHZ), CPUTYPE, MODELNUM, NUMCPU가 있다.
이는 CI용 설정이며 ACTCI 분류에 자동 적용되는 단위가 아니다.

### CI.COMPUTERSYSTEM 18개와 Actual CI 대조 — 2026-09-14

위 선택 분류 쿼리 재실행 결과: `local/db-access-kit/work/computer-classification-20260914/`.
CI.COMPUTERSYSTEM은 CCI00015(CI 적용), SYS.COMPUTERSYSTEM은 CCI10470(ACTCI 적용),
SYS.VIRTUALCOMPUTERSYSTEM은 CCI10793(ACTCI 적용)이다.

CI.COMPUTERSYSTEM의 18개를 ASSETATTRID·SECTION으로 대조하면 두 ACTCI 분류 각각에서
모두 한 개의 템플릿과 대응한다. 두 ACTCI 분류의 전체 스펙은 각각 98개다.
대응한 ASSETATTRIBUTEID·DATATYPE·분류/속성 단위·DOMAINID·MANDATORY·USEINSPEC은 모두 일치한다.
SECTION·단위·DOMAINID는 공란, MANDATORY=0, USEINSPEC=1이다. 단위 공란은 저장 단위가 정해졌다는 뜻이 아니다.
CLASSSPECUSEWITH 적용 객체는 CI 쪽 CI, Actual 쪽 ACTCI이며 템플릿 ID는 분류별로 구분한다.

공통 접두어 `COMPUTERSYSTEM_`를 생략한 18개 목록:

| 자료형 | 속성 |
| --- | --- |
| NUMERIC (3개) | CPUSPEED, MEMORYSIZE, NUMCPUS |
| ALN (15개) | ARCHITECTURE, CPUTYPE, FQDN, MANAGEDSYSTEMNAME, MANUFACTURER, MODEL, NAME, PRIMARYMACADDRESS, SERIALNUMBER, SIGNATURE, SYSTEMBOARDUUID, TYPE, UUID, VIRTUAL, VMID |

BIOS 관련 속성과 CPUCORESINSTALLED·CPUCORESENABLED는 이 18개에 포함되지 않는다.
CI.VIRTUALCOMPUTERSYSTEM(CCI00112)에 직접 등록된 스펙은 14개이며, 위 목록 중
MANAGEDSYSTEMNAME·SIGNATURE·SYSTEMBOARDUUID·UUID가 없다. 승격 시 상속·값 전달 동작은 이번 조회에서 시험하지 않았다.

### Computer 추가 스펙·단위 재대조 — 2026-09-14

[BIOS 속성·단위 조회](../../exploration-queries/maximo/computer-ci-mapping-audit.sql)와
[Device 매핑](../../data-mapping/ci/types/device.md#5-조회-sql)의 템플릿 SELECT를 실행했다.
결과: `local/db-access-kit/work/computer-ci-mapping-20260914-maximo/`.

- 두 ACTCI 분류 모두 BIOSMANUFACTURER·ROMVERSION(ALN), CPUCORESINSTALLED(NUMERIC)가 있다. 접두어는 COMPUTERSYSTEM_다.
- BIOSDATE는 NUMERIC이다. 날짜 인코딩 규약은 이번 조사에서 확인되지 않았다.
- 매핑 문서에서 추가 정의한 COMPUTERSYSTEM_BIOSRELEASEDATE는 ASSETATTRIBUTE·분류 템플릿에 현재 없다.
- MEASUREUNIT에는 GBYTE(GB), MBYTE(MB), GHZ, MHZ가 있다. 해당 Computer 템플릿의 단위는 공란이며, 단위 코드 존재와 템플릿 적용은 별개다.
- IBM은 ROMVERSION을 컴퓨터 메인보드의 BIOS 버전으로 설명한다. [CCMDB 가이드, 인쇄 페이지 371](https://www.redbooks.ibm.com/redbooks/pdfs/sg247879.pdf)
- IBM의 ComputerSystem 매핑은 TYPE을 ComputerSystem으로 명시한다. [ComputerSystem class](https://www.ibm.com/docs/en/tivoli-monitoring/6.3.0?topic=cdm-computersystem-class)

## 3. 확인된 주요 스펙

`ALN`은 문자열, `NUMERIC`은 숫자다. 이름과 자료형을 확인한 목록이며 원천 필드와의 의미 일치를 자동 보증하지 않는다.
괄호 안 접두어와 아래 접미어를 이어 붙인 것이 실제 ASSETATTRID다.

| 분류 | 주요 스펙과 자료형 |
| --- | --- |
| SYS.COMPUTERSYSTEM / SYS.VIRTUALCOMPUTERSYSTEM | (COMPUTERSYSTEM_) NAME, SERIALNUMBER, UUID, MODEL, MANUFACTURER, TYPE, VIRTUAL: ALN; MEMORYSIZE, NUMCPUS, CPUCORESINSTALLED, CPUCORESENABLED, CPUSPEED: NUMERIC; CPUTYPE: ALN |
| 같은 Computer 분류 — BIOS | (COMPUTERSYSTEM_) BIOSMANUFACTURER, BIOSNAME, ROMVERSION: ALN; BIOSDATE: NUMERIC |
| SYS.CPU | (CPU_) CPUCORESINSTALLED, CPUCORESENABLED, CPUSPEED, NUMCPUS, IDENTIFYINGNUMBER: NUMERIC; MANUFACTURER, CPUTYPE, INDEXORDER, VERSIONSTRING: ALN |
| SYS.MEMORY | (MEMORY_) MEMORYSIZE: NUMERIC; BASEADDRESS, VERSIONSTRING: ALN |
| DEV.DISKDRIVE | (MEDIAACCESSDEVICE_) NAME, MODEL, MANUFACTURER, SERIALNUMBER: ALN; DISKDRIVE_DISKSIZE: NUMERIC; DISKDRIVE_DISKINTERFACETYPE, PRIMARYDISKINTERFACETYPE, SECONDARYDISKINTERFACETYPE: NUMERIC; DISKDRIVE_ISSOLIDSTATE: ALN |
| SYS.FILESYSTEM | (FILESYSTEM_) MOUNTPOINT, TYPE, VERSIONSTRING: ALN; CAPACITY, AVAILABLESPACE: NUMERIC |
| SYS.OPERATINGSYSTEM | (OPERATINGSYSTEM_) NAME, OSNAME, OSVERSION, VERSIONSTRING, BUILDLEVEL, KERNELVERSION: ALN; MAJORVERSION, OSID: NUMERIC |
| NET.L2INTERFACE | (L2INTERFACE_) NAME, HWADDRESS, PHYSICALLOCATIONCODE: ALN; SPEED, MTU, INDEX: NUMERIC |
| NET.IPINTERFACE | IPINTERFACE_PORTLIST: ALN; IPINTERFACE_STATUS: NUMERIC; MAC·속도 전용 스펙은 없음 |
| NET.IPADDRESS / NET.IPV4ADDRESS / NET.IPV6ADDRESS | (IPADDRESS_) STRINGNOTATION, DOTNOTATION, BYTENOTATION, ADDRESSSPACE: ALN; ADDRESSTYPE: NUMERIC |
| NET.IPNETWORK | (IPNETWORK_) SUBNETADDRESS, NETMASK, NAME, ADDRESSSPACE: ALN; PREFIXLENGTH: NUMERIC |
| APP.SOFTWAREINSTALLATION | (SOFTWAREINSTALLATION_) PRODUCTNAME, VERSIONSTRING, MANUFACTURERNAME, INSTALLEDLOCATION: ALN; MAJORVERSION: NUMERIC |
| APP.SOFTWAREPRODUCT | (SOFTWAREPRODUCT_) PRODUCTNAME, VERSIONSTRING, MANUFACTURERNAME, PRODUCTID, TYPE: ALN |
| APP.SOFTWAREIMAGE | (SOFTWAREIMAGE_) IMAGENAME, IMAGEVERSION, CHECKSUM: ALN;INSTALLEDLOCATION 스펙 없음 |
| APP.SOFTWAREMODULE | (SOFTWAREMODULE_) NAME, FILENAME: ALN;설치 제품의 이름·버전·경로 전용 스펙 묶음은 없음 |
| PHYS.PHYSPKG.CARD / PHYS.PHYSPKG.SYSTEMBUSCARD | (PHYSICALPACKAGE_) NAME, MODEL, MANUFACTURER, SERIALNUMBER, PARTNUMBER: ALN; RELATIVEPOSITION: NUMERIC;GPU 전용 메모리 스펙은 확인되지 않음 |

Computer 스펙에는 전체 디스크·마운트·OS·설치 SW 목록을 각각 표현하는 전용 반복 필드가 없다.
PRIMARYMACADDRESS는 ALN 단일 값이다. 여러 인터페이스의 MAC 목록과 동일한 표현은 아니다.

SYS.MEMORY에는 모듈 슬롯·모델·제조사·시리얼을 각각 담는 전용 스펙이 없다.
MEMORY_BASEADDRESS는 이름상 메모리 주소이며 슬롯명으로 확인된 필드가 아니다.
SYS.CPU의 IDENTIFYINGNUMBER는 NUMERIC이며 문자열 시리얼의 직접 수용 필드로 확인되지 않았다.
OS의 BUILDLEVEL은 ALN이지만 원천 버전 번호와의 의미 대응은 별도다.

분류 ID·DESCRIPTION에서 GPU·GRAPHIC·VIDEO·BIOS를 검색했을 때 GPU/BIOS 전용으로 바로 대응할 분류는 확인되지 않았다.
CARD·SYSTEMBUSCARD 같은 범용 물리 분류는 존재한다. 단순 명칭 검색으로 전체 모델에서 표현 불가능하다고 결론 내리지는 않는다.

## 4. 관계 규칙

표는 조회된 SOURCECLASS→TARGETCLASS 방향이다. 각 RELATIONNUM은 RELATION에도 존재한다.
`C`는 SYS.COMPUTERSYSTEM 또는 SYS.VIRTUALCOMPUTERSYSTEM이며, 표에서 C를 쓴 규칙은 두 분류 각각에 존재한다.
REVRELATIONSHIP·SWAPPED는 설정 원문이다. 실제 적재에서 출발·도착을 임의로 뒤집지 않는다.

| 출발 → 도착 | RELATIONNUM | CARDINALITY | CONTAINMENT | REVRELATIONSHIP | SWAPPED |
| --- | --- | --- | --- | --- | --- |
| C → SYS.CPU | RELATION.CONTAINS | 1:N | 1 | 0 | 0 |
| C → DEV.DISKDRIVE | RELATION.CONTAINS | 1:N | 1 | 0 | 0 |
| C → SYS.FILESYSTEM | RELATION.CONTAINS | 1:N | 1 | 0 | 0 |
| C → NET.L2INTERFACE | RELATION.CONTAINS | 1:N | 1 | 0 | 0 |
| C → NET.IPINTERFACE | RELATION.CONTAINS | 1:N | 1 | 0 | 0 |
| C → SYS.MEMORY | RELATION.CONTAINS | 1:1 | 1 | 0 | 0 |
| SYS.OPERATINGSYSTEM → C | RELATION.INSTALLEDON | N:1 | 1 | 1 | 1 |
| SYS.OPERATINGSYSTEM → C | RELATION.RUNSON | 1:1 | 0 | 1 | 1 |
| APP.SOFTWAREINSTALLATION → SYS.OPERATINGSYSTEM | RELATION.INSTALLEDON | N:1 | 1 | 1 | 1 |
| NET.IPINTERFACE → NET.IPADDRESS | RELATION.BINDSTO | 1:1 | 0 | 1 | 0 |
| NET.IPINTERFACE → NET.L2INTERFACE | RELATION.BINDSTO | 1:1 | 0 | 0 | 0 |
| NET.IPADDRESS → NET.IPNETWORK | RELATION.MEMBEROF | 1:1 | 0 | 0 | 0 |
| SYS.VIRTUALCOMPUTERSYSTEM → SYS.COMPUTERSYSTEM | RELATION.VIRTUALIZES | 1:1 | 1 | 1 | 1 |

정확한 분류쌍으로 조회했을 때 다음 직접 규칙은 없다.

- C ↔ NET.IPADDRESS / NET.IPV4ADDRESS / NET.IPV6ADDRESS.
- NET.L2INTERFACE ↔ NET.IPADDRESS / NET.IPV4ADDRESS / NET.IPV6ADDRESS.
- APP.SOFTWAREINSTALLATION ↔ C.
- C → PHYS.PHYSPKG.CARD / SYSTEMBUSCARD의 CONTAINS. 다른 의미의 RUNSON·REALIZES 규칙은 존재한다.

RELATION 코드가 다른 분류쌍에 있다는 이유로 위 직접 규칙이 존재한다고 해석하지 않는다.
클래스 계층 상속·SWAPPED의 실제 UI 처리와 원천 다중 연결에 대한 적용은 이번 조회로 검증하지 않았다.

## 5. 조사 범위

현재 설정의 분류 계층, 선택 분류의 스펙 적용·타입·단위, 정확한 분류쌍 관계를 확인했다.
D42 원천 행 수·값 보유율은 이번 비교의 판단 기준으로 사용하지 않았다.
전체 원천 항목의 사용 여부·보완 제안은 수집 설계에, 남은 범위 결정은 ISSUE-8, 의미·단위·관계 검증 항목은 ISSUE-11에 둔다.
